# RTSS 能力判断与固定门槛整改 TODO

日期：2026-10-09。分支：`feature/069-rtss-target-frame-rate`，审查基线 `369db4e2`。状态：审查与规划完成，14 项实现和验证任务待执行；本轮没有修改功能代码。

RTSS 功能按当前操作实际需要的接口、字段、文件访问和运行条件判断可用性。版本号用于显示、日志和验证记录，不能作为准入白名单；未测试版本不等于不兼容。某项能力缺失时，只限制依赖它的操作。

## 已确认的类似设计

| 位置 | 当前判断及影响 | 整改方向 |
| --- | --- | --- |
| `RtssProfileAccess::InitializeUnlimited` | 写入前要求版本精确等于 7.3.5.28314；新版本、旧版本和读取不到版本号都会被拒绝。已有不限帧配置在此判断前只读返回 | 移除版本门槛，依据实际配置结构、所需能力及读回验证决定写入路径 |
| `RtssProfileAccess::Initialize` | Load、Save、Delete、Get、Set、Update 六个导出必须齐全，否则整个配置接口不可用；缺 Delete 也阻止读取和独立初始化 | 按操作记录导出能力；读配置不依赖 Save/Set/Delete，初始化不依赖与所选写入路径无关的导出 |
| `Initialize` 与 `_Read` | FramerateLimit、分母、FrametimeLimit、AppDetectionLevel 任一 getter 失败就整体失败 | 区分当前操作必需字段与可选信息。读不到的值保持未知，不能当作 0、关闭或默认分母 |
| `RtssService::_Prepare`、`Preview` 与 `CanInitializeMagpie` | 未运行在统一准备阶段直接返回，后续只读预览和初始化也被挡住 | 分开运行状态、离线读取、持久保存和运行中重载；验证可用的离线操作独立开放，实时限帧仍等待工具运行 |
| `InitializeUnlimited` 与 `ResolveTarget` | 初始化只接受固定的 Magpie.exe；目标解析也额外排除此名称。即使 worker 已取得真实自身文件名，改名程序仍被拒绝 | 使用可信的当前程序文件名和进程身份；同名 RTSS 配置冲突单独处理，不通过固定产品文件名替代身份检查 |
| `DetectTool` | 只从注册表及 Program Files 两个默认位置查找，查找失败归为未安装；便携或未注册路径可能未被识别 | 补充实际运行进程路径等发现来源，保持程序、DLL 与配置目录属于同一安装；找不到路径不直接推断所有能力不存在 |
| `ProfileFailureText` 与资源 | UnsupportedProfileFormat 和 InvalidSelfProfile 共用“此版本的配置格式尚未支持” | 按实际原因区分格式、初始化对象、缺失接口、架构和权限，使用简短事实文案 |

## 需要进一步核实的实现边界

| 边界 | 已确认事实 | 处理原则 |
| --- | --- | --- |
| ARM64 | 编译为 ARM64 时在加载前直接拒绝；本机 RTSSHooks64.dll 的 PE Machine 为 0x8664 | 不能宣称去掉条件后即可调用本机 DLL。按实际架构/ABI及加载结果判断 SDK 能力，并与不调用 DLL 的文件读取分开 |
| 文件解析 | UTF-16/含 NUL 输入被拒绝；任意节出现重复键都会使 `_ReadFile` 失败，未区分是否为本次限帧字段 | 判断当前操作能否可靠读取、修改并验证。限帧表达歧义继续拒绝；非限帧内容能够原样保留时，评估避免整项拒绝。不能把解析器边界解释为 RTSS 版本过老 |
| 参数加载 | `ReadProfileRtss` 任一已知字段无效就把 scope 设为 None；`IsValid` 在同步模式下仍检查未使用的 customRate | 现有未知操作禁止外部写入的规则保留；评估未使用字段的局部恢复，不因它损坏就丢弃其他有效选择 |
| 帧率数值 | 手动范围为 15–360，同步和 Apply 另有 1000 上限；本机 SDK 示例的 FramerateLimit 注释没有给出跨版本最大值 | 区分既有产品输入范围、数值表示边界与 SDK 实际可接受范围。本轮不自行改动所有刷新输入；内部上限需要明确依据，不把它写成 RTSS 的统一能力结论 |
| 帧时间与恢复 | 当前正 FPS 路径实际 setter 拒绝清零时失败；原字段缺失关系变化时恢复验证失败 | 这是已观察到的表达能力问题，承接保存失败 C01。通过实际返回和经过验证的字段路径处理，不降低恢复一致性标准，也不再增加版本白名单 |

参数依据：[设置模型](../../../src/Magpie/RtssSettings.h)、[偏好加载](../../../src/Magpie/ProfileRtss.h)、[字段清零](../../../src/Magpie/RtssProfileExpression.h)。

## 能力模型与版本整改

- [ ] **T01** 移除初始化的精确版本判断及其合同预期。相同能力和配置结构在旧版、新版或版本号未知时采用相同处理；未知结构或实际接口失败仍按具体原因结束。日志保留版本，但不参与准入决定。
- [ ] **T02** 拆分定位目录、磁盘读取、API 读取、属性设置、SDK 保存、字段写入、重载和受控删除能力，并列出各命令实际依赖。能力缓存绑定实际加载的模块和配置目录，重新检测时处理失效；修正六导出全有才可用的聚合判断：例如缺 Delete 不阻止独立读取。创建目标并选择恢复时，结束策略必须有可行路径，不暗中改为保留修改。
- [ ] **T03** 按操作检查必需 getter，将其他信息保留为未知或单独不可用。缺少检测级别查询不直接等于 FPS 不可写，缺少帧时间查询也不能直接等于没有帧时间限制。具体 setter 的值支持在用户请求的事务内依实际返回和读回判定；页面预览不通过试写用户配置来探测能力。

## 运行条件与实际对象

- [ ] **T04** 拆分 `_Prepare` 的安装发现、运行检测、配置访问与重载准备。离线读取可用时显示实际配置；离线初始化只有在相应持久保存和校验能力通过后才开放。区分“配置已保存”“RTSS 未运行”和“重载完成”，停止缩放后的旧请求不能因启动工具重新兑现；不自动启动工具。
- [ ] **T05** 初始化对象由可信的当前程序路径取得并在完整事务中绑定，去掉固定 Magpie.exe 名称比较。沿用合法 exe 名称和无损 ANSI 转换要求，确保不会写到 Global 或所选游戏。自进程排除以进程身份为依据；RTSS 按 exe 名称共享配置，同名对象的冲突要单独识别，不能同时保证游戏限帧和自身不限帧。
- [ ] **T06** 补充运行进程路径等工具发现来源，覆盖便携路径和注册表过期。多个候选时先确认实际程序、DLL、配置目录的一致性，不能混用不同安装或按文件名猜测路径；无法唯一定位时保留具体发现结果，不静默写入任一目录。
- [ ] **T07** 审核 ARM64 的提前拒绝，采用实际架构/ABI及加载结果判定 SDK 能力。保留真实的不兼容结果；无可调用 SDK 时只开放已经实现并验证的独立文件能力，不假定存在原生 ARM64 RTSS DLL，不重新调用已异常的模块。

## 格式边界与界面状态

- [ ] **T08** 细化当前解析器的字段和编码能力。按本次要读写的表达判断，不因无关节的重复项一概禁止可验证的限帧操作；支持新增编码前验证 RTSS 的实际读回。歧义限帧键、无效分母及无法保留原内容的情况继续拒绝该次写入，保留原字节、非限帧字段和竞争检查。
- [ ] **T09** 细化 RTSS 偏好校验：同步模式下未使用的手动字段损坏不直接抹掉有效管理范围；对必要参数无效和未知操作继续停止外部写入，不把未知枚举解释为 Global、Target 或保留修改。加载、显示、保存和执行统一记录字段是否有效，避免下一次保存把整份有效选择重置为不管理。
- [ ] **T10** 核实 15–360 与 1000 的来源和用途，区分产品范围与底层接口边界。保留整数、有限值、有效分母及转换不溢出的校验；如调整 RTSS 输入范围，单独处理其持久参数和验证，不连带放开全部内容/光标/空闲重绘输入，不伪造 SDK 没有暴露的最大值。
- [ ] **T11** 用操作能力更新初始化、读取及其他控件的可用状态，替代单一 accessReady 的整项开关。分别映射接口、对象、格式、架构、权限和重载原因，更新 20 份资源。继续采用同段简短事实提示，不因未测试版本显示“不支持”，不把磁盘值冒充当前实时 FPS。

## 回归验证与文档

- [ ] **T12** 替换“其他版本必须失败”的测试，建立相同能力/不同版本和相同版本/不同能力的回归。覆盖未知版本、缺 Delete、仅能读取、缺可选 getter、具体 setter 拒绝、离线条件、实际自身改名、便携路径、多安装、字段局部损坏、格式歧义和部分写入。继续覆盖已不限帧零写入、游戏会话与初始化交错、权限/外部编辑、一次恢复和接口异常隔离。
- [ ] **T13** 对实际可取得的 RTSS 样本运行隔离原生事务，记录实际加载 DLL 的路径/指纹、目录来源及读回结果，证明本次使用的能力，而非只记录 RTSS.exe 的版本。其他样本无法取得时记录验证待补，不加运行白名单；不停止用户 RTSS、不通过用户配置试探范围。离线原生测试要明确是否仍有其他 RTSS 实例运行，不能只给 tool.running=false 就声称验证了完全离线。产品编译、真实 UI、运行中重载与目标/Magpie FPS 验收继续交给独立会话。
- [ ] **T14** 更新功能设计、能力依赖表、状态说明、源码合同和实施记录。保存失败 C01 的表达兼容按实际字段/接口处理；C02 改为能力验证记录，不产出版本准入名单。旧实施记录保留当时的硬门槛事实，并链接本次整改及后续结果。

## 保留的明确规则

实际权限失败、DLL 加载/ABI错误、分母为零、目标 HWND/PID/创建时间不匹配、用户配置竞争、原值与最后写入的所有权核对、异常模块隔离、停止只恢复一次及有限资源读取，均有具体条件，应继续保留。Magpie 自身设置的迁移版本标记属于一次性数据迁移，不是 RTSS 版本准入，继续保留用户之后的管理员启动选择。

新目标配置 Low、已有目标保留检测设置、自身初始化保留检测/OSD、固定帧率行、整数输入和两种停止策略保持既有要求。本轮只规划，不改变这些已确认行为。
