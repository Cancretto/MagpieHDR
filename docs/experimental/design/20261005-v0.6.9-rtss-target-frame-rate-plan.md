# RTSS 目标窗口帧率限制功能规划

日期：2026-10-05（Asia/Shanghai）。适用：Magpie 0.6.9 配置页。状态：功能设计；已进入 `feature/069-rtss-target-frame-rate` 源码开发，编译与 RTSS 联动实测未进行。当前进度见[开发与交接清单](../todos/20261005-v0.6.9-rtss-target-frame-rate-TODO.md)。

本功能让用户在 Magpie 中设置目标窗口所属应用的 RTSS 帧率上限。Magpie 负责识别目标、读写 RTSS 配置及处理会话结束策略，目标应用内的 RTSS Hook 负责实际限帧。功能入口位于配置页“帧率与刷新”分组中，在“内容帧率”之前。

## 已明确的需求

| 部分 | 用户要求 |
| --- | --- |
| 目标窗口帧率限制 | 提供“不管理 RTSS 配置”“修改全局配置”“修改目标窗口配置”三个选项 |
| RTSS 状态 | 显示安装、版本、配置读取和失败状态，右侧提供启动 RTSS 和 MSI Afterburner 的选项 |
| 帧率设置 | 用户自行输入整数帧率，或与内容帧率自动同步；内容“跟随源”时同步不可用 |
| 高级选项 | 提供“保留修改”“恢复原值”两个策略；恢复只作尽力尝试，失败后结束 |
| 写入时机 | 开始缩放时自动应用；编辑配置页只保存 Magpie 设置 |

“修改全局配置”直接修改 RTSS Global。“修改目标窗口配置”先检查对应应用是否已有独立配置；没有则创建并自动应用基础的 Application Detection Level Low，有则修改该配置的帧率。高级选项提供保留修改或恢复原值两个策略。

下文的默认值、数值范围及具体控件形式是实现建议，未标为用户明确要求的部分可在文档审查时调整。

## 页面布局

```text
帧率与刷新
├─ 目标窗口帧率限制          不管理 RTSS 配置 / 修改全局配置 / 修改目标窗口配置
│  ├─ RTSS 状态             状态说明、配置对象、读取到的上限    [启动工具 ▾]
│  │                       右侧菜单：启动 RTSS / 启动 MSI Afterburner
│  ├─ 帧率设置              自定义 / 与内容帧率自动同步
│  │  ├─ 限制帧率           自定义时可编辑，单位 FPS
│  │  └─ 同步目标           同步时显示解析出的基础目标或等待原因
│  └─ 高级选项              默认折叠
│     └─ 停止缩放后的处理    保留修改 / 恢复原值
├─ 内容帧率                 跟随源 / 自动 / 自定义
│  ├─ 节奏控制方式
│  └─ 目标基础帧率
├─ 光标刷新方式
└─ 高级选项                 现有重复帧检测和空闲重绘设置
```

新增“高级选项”从属于目标窗口帧率限制，与现有刷新高级选项区分层级。默认配置与应用配置采用相同布局；控件沿用当前配置页的样式、225 DIP 控件列和窄窗口换行规则。

选择“不管理 RTSS 配置”时保留用户的帧率和结束策略，禁用写入相关控件。RTSS 状态仍可查看，并明确显示“当前 Magpie 不管理 RTSS 配置”；启动工具入口仍可使用。界面中不显示 Hook 地址、导出函数、配置键名等实现细节。

## 目标窗口帧率限制

| 选项 | 行为 | 影响范围 |
| --- | --- | --- |
| 不管理 RTSS 配置 | 不接管 RTSS 配置，不创建配置，不写入 0 | RTSS 原有设置继续自行生效 |
| 修改全局配置 | 读取 Global 原值并设置本次上限 | 使用 Global 的应用；不强制覆盖目标应用已有独立上限 |
| 修改目标窗口配置 | 定位实际目标 exe，检查独立配置，创建或更新其帧率 | 使用同一 RTSS 应用配置的实例 |

“不管理 RTSS 配置”直接说明喜鹊没有接管 RTSS，不暗示目标已经解除限帧。用户选择全局模式后，界面简短说明“影响使用 RTSS 全局配置的应用”；如果目标已有独立配置，则提示“目标存在独立配置，全局上限可能不作用于此目标”。

如果 Magpie 本身也使用 Global，其呈现同样可能受到全局上限影响，尤其需要检查补帧输出。已有 Magpie 独立不限帧配置时按其原设置运行；本功能不为规避全局影响而静默创建或修改 Magpie 的 RTSS 配置。

界面保持“目标窗口配置”的名称。实际配置按 RTSS 的应用匹配规则定位，通常对应 exe；同一 exe 的多个窗口不能保证使用不同上限。配置信息显示实际应用名称，避免用户误以为这是单个 HWND 的限帧。

### 目标配置检查与创建

1. 开始缩放时，根据实际捕获目标确认渲染应用身份，记录 exe、进程身份和缩放会话代次。
2. 使用配置枚举或可靠的配置存在性检查判断独立配置是否存在。不能仅凭 `LoadProfile` 成功判断存在，因为缺失配置会回退读取 Global。
3. 已存在时读取原帧率，只更新限帧相关字段，保留检测级别、OSD、Reflex、扫描线同步及其他设置。
4. 不存在时读取 Global 作为新配置的基础，将新配置的 `AppDetectionLevel` 设置为 Low，并写入本次整数帧率，保存为目标 exe 的独立配置，再核实创建结果。目标模式不得误保存到 Global。
5. 新建配置使用 Low 是本功能明确的基础策略，避免继承 Global 的检测关闭后无法检测目标。除检测级别和本次限帧字段外，其余设置继承 Global。已有目标配置继续保留原检测级别；若其检测关闭，则显示状态，不套用新建配置的 Low 初始化规则。

对于 UWP、宿主窗口和默认 Magpie 配置，必须以本次实际目标解析 RTSS 应用身份，不能直接把 Magpie 的配置规则或 AUMID 当作 exe，也不能错误限制宿主或 Magpie.exe。无法可靠识别时停止本次 RTSS 写入，正常缩放可以继续。

## RTSS 状态

状态区同时说明“是否能访问 RTSS”和“本次配置操作走到了哪一步”。安装成功、配置读取成功或写入成功，均不能单独证明游戏已被 Hook 或实际达到目标帧率。

| 状态 | 建议显示 | 操作行为 |
| --- | --- | --- |
| 未管理 | 当前 Magpie 不管理 RTSS 配置 | 展示工具状态和启动入口，不写入配置 |
| 未安装 | 未找到 RTSS | 保留 Magpie 设置，跳过外部写入 |
| 版本过老或不兼容 | 当前 RTSS 版本不支持所需配置接口 | 显示检测到的版本，允许重新检测 |
| 未运行 | RTSS 未运行，等待启动 | 右侧提供启动选项；缩放可以继续，本次限帧等待工具可用 |
| 正在启动 | 正在启动所选工具 | 防止重复启动，异步刷新状态 |
| 启动失败 | 所选工具未能启动，显示原因 | 结束本次启动尝试，允许用户再次操作 |
| 正在检查 | 正在检查 RTSS | 异步执行，不阻塞配置页 |
| 等待目标 | 开始缩放后读取目标窗口配置 | 默认配置或尚未确定实际目标时使用 |
| 正在读取配置 | 正在读取 Global 或目标配置 | 未完成读取前不能覆盖原值 |
| 配置已读取 | 当前配置上限为 xx FPS，或未限制 | 展示当前值；仅预览，不修改 RTSS |
| 未找到目标配置 | 开始缩放时将创建目标配置 | 只读检查阶段不创建文件 |
| 正在创建或写入 | 正在应用 xx FPS | 防止同一会话重复提交 |
| 已写入 | 已写入 xx FPS，并已请求 RTSS 重新读取 | 不标为“实际限帧已生效” |
| 同步目标不可用 | 内容帧率没有固定目标，未写入 RTSS | 保留原值，说明等待原因 |
| 应用检测关闭 | 配置已写入，但 RTSS 未启用此应用的检测 | 用于已有目标配置；新建目标配置自动使用 Low |
| 操作失败 | 显示失败阶段及可读原因 | 提供重试，不阻止 Magpie 正常缩放 |
| 已保留或已恢复 | 已保留本次上限，或已恢复原值 | 反映实际操作结果 |
| 恢复冲突 | RTSS 配置已被其他操作修改，未覆盖 | 保留外部修改，提供查看信息 |
| 恢复失败 | 已尝试恢复，但未完成，显示原因 | 记录原因后结束，不阻塞退出，不自动反复重试 |

“版本过老”依据经过验证的版本兼容表和实际接口能力判断。DLL 缺失、位数不符、目录无权限和运行时加载失败，应分别归入相应失败原因，不能一概显示版本过老。最低支持版本在实现阶段验证后确定；目前只能确认本机 7.3.5.28314 随附 SDK 提供相关接口。

RTSS 未运行时能否可靠执行离线配置读写，需在实现阶段验证；验证前不承诺离线写入能力。状态区可以重新检测，不自动下载、安装或升级 RTSS。

### 状态右侧的启动入口

右侧提供“启动工具”菜单，包含“启动 RTSS”和“启动 MSI Afterburner”。宽窗口中入口与状态同行靠右；窄窗口中允许换行，但仍从属于同一状态行。

分别检测两个工具的安装与运行状态。未安装的启动项不可用并说明原因，已运行的项目显示已运行状态，避免重复启动。入口只启动用户选择的工具；不会因为选择了 RTSS 就同时启动 MSI Afterburner，也不会未经点击在后台启动工具。

本功能的限帧可用条件仍以 RTSS 为准。MSI Afterburner 是用户可选的启动项目，不把它未安装或未运行视为 RTSS 限帧失败。启动 MSI Afterburner 后重新检查 RTSS 是否实际运行，不假定前者一定会带起后者。

开始缩放时若 RTSS 未运行，本次限帧请求保持等待状态。用户点击启动工具后，重新检查 RTSS；可用时为仍然有效的同一缩放会话完成首次应用，无需用户停止并重新开始缩放。不在工具不可用期间修改配置，不把该等待流程变成每帧或无限重试。

只有当前会话和目标仍有效时才能完成等待中的写入。停止缩放后，不再兑现旧请求，也不自动关闭用户启动的 RTSS 或 MSI Afterburner。结束策略仅处理 RTSS 配置。

## 帧率设置

### 自定义

用户输入需要的源应用整数上限，单位 FPS，不提供小数帧率输入。首版建议沿用现有内容输入的 15–360 FPS 整数编辑范围，默认保存 60 FPS；这属于界面建议，不代表 RTSS 本身只支持此范围。

手动数值按整数编辑规则处理，显示值、保存值与写入值一致。空值、NaN、无穷或越界输入不能触发外部写入。切换到自动同步时保留手动值；切回自定义时恢复该值。“不管理 RTSS 配置”负责退出本功能管理，不使用手填 0 同时表达禁用和数值上限。

### 与内容帧率自动同步

同步方向为“Magpie 内容基础目标 → RTSS 源应用上限”。复用当前内容目标解析结果，不另建一套与 Renderer 不一致的公式，不按实时测得的 FPS 调节，也不把插帧后输出帧率、光标刷新率或空闲重绘率写给 RTSS。

| 内容帧率模式 | 同步规则 |
| --- | --- |
| 自定义 | 取本次会话解析后的基础内容目标，转换成整数上限；如果兼容约束改变有效值，显示实际同步值及原因 |
| 自动 | 按当前输出显示器刷新率、实际补帧倍率及已有基础限制解析，再转换成整数上限；不直接写入代表自动的 0 |
| 跟随源 | 禁用“与内容帧率自动同步”选项，并说明没有固定目标；仍允许自定义 RTSS 上限 |

例如，在没有其他基础限制时，144 Hz、两倍补帧对应基础目标 72 FPS；RTSS 同步为 72，而不是 144。无补帧、自定义内容目标 60 时同步为 60。上述为规则示例，非实测结果。

自动解析可能产生小数，但本功能只写入整数。整数转换建议沿用现有整数编辑的四舍五入规则，例如 119.88 Hz、两倍补帧得到基础目标 59.94 时，RTSS 写入 60 FPS。界面显示实际写入的整数值；Magpie 原有基础目标仍保留其自身精度，不随 RTSS 整数化而改变。取整是本功能内部的统一规则，不新增取整方式选项。

已经选择自动同步后，如果内容模式变成“跟随源”，保留保存的同步偏好但显示不可用状态，不隐式改用手动值，也不写入源 FPS 估计值。用户可以主动改为自定义；恢复固定内容目标后，原同步偏好重新可用。

会话中显示器、倍率或有效基础目标变化时，自动同步重新解析并更新。相同目标不重复写入，连续变化合并处理；不得在每帧调用磁盘写入，也不能把先前已解析的自动值持久化成 Magpie 自定义目标。

## 高级选项

用户选择本次修改在真正停止缩放后如何处理。首版建议默认“恢复原值”；该默认值是建议，两个策略均向用户开放。

| 策略 | 正常结束时的行为 |
| --- | --- |
| 保留修改 | 保留本次最后成功写入的 RTSS 帧率及本次创建的目标配置；明确显示修改持续有效 |
| 恢复原值 | 尽力尝试恢复第一次写入前的限帧状态；原本没有目标配置时，按下文规则尝试恢复继承 Global 的状态 |

### 原值的范围

只恢复本功能管理的限帧字段。原始状态包含“是否已有独立配置”和完整帧率表达。虽然本功能只设置整数 FPS，用户原有 RTSS 配置仍可能采用小数或帧时间表示，因此原值快照保留其表示方式，恢复时按原样尝试还原。保留原值精度不意味着新增小数输入功能。其他 RTSS 设置不因恢复操作被覆盖。

原值必须在第一次外部修改之前记录。内部参数重启、窗口重建、显示器变化及自动同步更新不能再次把本功能已经写入的值记录为“原值”。

### 已有配置的恢复

停止时重新读取当前限帧值；只有仍符合本功能最后写入状态时，才恢复原限帧状态。用户或其他工具已修改限帧时，不覆盖其修改，显示恢复冲突。其他字段发生独立修改时保留这些字段，不进行整份配置回滚。

切换为“不管理 RTSS 配置”时，先按照当前会话所选的结束策略尝试释放本功能对 RTSS 的管理，再停止后续写入；不能把该选项隐式实现为写入无限制。恢复失败也不阻止退出管理。

### 新建目标配置的恢复

如果会话前没有独立目标配置，恢复原状态意味着撤销本次创建的配置，让目标重新使用 Global，而不是留下一个只把上限改回去的独立配置。

只有该配置仍能可靠判断为本次创建、且期间未被用户或其他工具修改时才删除。发现外部修改或无法可靠确认归属时保留配置并报告冲突。RTSS 预置配置及不是本会话创建的配置不得删除。

恢复继承关系后采用当时的 Global。如果会话期间 Global 被用户调整，目标将跟随新的 Global；状态说明恢复的是配置继承关系，不声称仍使用会话开始时的数值。

### 尽力恢复与异常结束

原值快照保存在本次会话内，至少包含配置对象、原限帧状态、创建标志、最后写入状态和会话身份。正常停止、开始失败、取消及能够执行清理的异常路径，按策略进行一次有界的恢复尝试；成功则显示已恢复，失败或冲突则记录原因后结束。

不要求保证恢复成功，不为恢复增加常驻监控助手、持久恢复任务或下次启动补偿，也不因恢复失败阻塞关闭或持续重试。进程崩溃、强制结束等无法执行清理的情况，不保证恢复，RTSS 可能保留最后写入值。

“保留修改”不执行恢复。两种策略的原值快照和成功状态均不能被复制到其他 Magpie 应用配置。

## 写入和会话流程

配置页编辑、打开页面、启动 Magpie 和复制配置均只保存或读取，不直接修改 RTSS。开始缩放时，按当时选中的 Magpie 配置自动应用。

```text
开始缩放
→ 固定本次 Magpie 配置与实际目标
→ 检查 RTSS 安装、能力及运行状态
→ 解析手动或同步目标
→ 读取并记录原配置状态
→ 按全局或目标模式创建及写入
→ 重新读取并核实保存值
→ 请求 RTSS 重载配置
→ 运行期间按需要更新同步目标
→ 真正停止时保留修改或恢复原值
```

开始失败、取消和部分初始化失败也按所选结束策略尝试处理已经成功写入的会话；不会把未写入的请求当作需要恢复的成功事务。恢复尝试失败后结束清理，不要求反复重试至成功。RTSS 操作失败时，Magpie 可以继续缩放并显示失败原因。

内部自动重建属于同一次逻辑会话，原值与所有权沿用。显式停止后重新启用属于新会话。若重新选择不同目标或写入范围，先按旧会话策略处理旧配置，再为新对象读取原值。

异步操作绑定会话代次及目标进程身份，旧请求不能写入新目标。写入发生后即使会话已取消，也要尝试必要的清理，不能因为回调过期而直接跳过本次恢复机会；失败处理仍遵守尽力恢复规则。

如果外部在运行期间修改了被管理的限帧字段，自动同步暂停后续写入并报告冲突；不能不断把用户修改覆盖回去。不同 Magpie 配置使用全局模式时会竞争同一个 Global，当前活动会话统一协调写入归属。

## RTSS 接入

首选用户已安装 RTSS 的公开配置接口，通过与 Magpie 位数匹配的 DLL 访问配置；不要求 RTSS 先自动 Hook Magpie。接口调用集中串行处理，不能让多个异步请求共享“当前加载配置”状态并互相串写。

核心读写接口为 `LoadProfile`、`GetProfileProperty`、`SetProfileProperty`、`SaveProfile`、`UpdateProfiles`，以及撤销本次新建配置时使用的 `DeleteProfile`。Global 的接口标识是空字符串，不是将显示文字 `Global` 直接作为应用名传入。

开发期对本机 `EnumProfiles` 的独立只读探测出现访问异常，首版按上文允许的“可靠配置存在性检查”读取 `Profiles/<exe>.cfg` 文件元数据，区分缺失、权限失败与已有配置；不调用该枚举导出，不将缺失配置的 Global 回退误当作独立配置。这是读取存在性和核实落盘，限帧写入仍使用公开接口，未引入直接改文件的兼容回退。

`FramerateLimit` 是接口属性；本机文件中的上限字段为 `[Framerate]` 下的 `Limit`，还存在分母和帧时间表示。实现前验证整数 FPS 的读取与写入，以及原帧率表达的快照和恢复，不把接口属性名当作文件字段名。新建目标配置还需验证 `AppDetectionLevel` 的 Low 设置与读回。

SDK 中 `SaveProfile` 和 `UpdateProfiles` 为 void 返回，不能把没有异常当作完整成功。保存结果需要重新加载、读回并核实必要的落盘状态；重载请求完成仅说明请求已发出，不证明目标实际生效。

直接改配置文件是候选兼容方案，首版不在接口失败后静默切换。若后续采用，必须单独验证版本格式、原内容保留、写入竞争、权限、落盘及运行时重载；不能整份重建用户的配置。

目标未被 Hook、应用检测关闭、全局限帧器关闭或已有目标独立设置覆盖 Global 时，配置写入成功也可能不产生预期结果。状态提示这些可确认的条件；无充分证据时使用“实际限帧未确认”，不宣称已经生效。

## 配置保存与实现位置

建议在 Magpie 的每个 Profile 中增加独立的 RTSS 设置对象，与现有 `frameRefresh` 并列保存。它属于源应用配置联动，不进入 Core 的 GPU 限帧器，也不增加捕获或呈现等待。

| 建议字段 | 含义 | 建议默认值 |
| --- | --- | --- |
| `scope` | None（不管理 RTSS 配置）、Global、Target | None |
| `rateMode` | Custom、ContentSync | Custom |
| `customRate` | 整数手动上限 | 60 FPS |
| `exitPolicy` | KeepChanges、RestoreOriginal | RestoreOriginal |

旧配置缺少此对象时为“不管理 RTSS 配置”，不会因升级修改 RTSS。新建应用配置按现有规则复制默认配置的设置；工具运行状态、目标 exe、原值及本次会话快照不随 Profile 复制。损坏或未知枚举恢复为不写入 RTSS 的安全默认值，保留其他有效 Magpie 配置。启动工具是状态区的用户操作，不增加自动启动或退出关闭工具的持久配置。

实现位置建议：

- `ProfilePage.xaml`、`ProfileViewModel`：四部分控件、显隐、状态、右侧工具启动菜单及用户偏好。
- `Profile.h`、`AppSettings.cpp`、`ProfileService`：字段保存、旧配置默认及复制规则。
- 独立 RTSS 配置访问模块：安装与能力检查、配置查询、写入验证和恢复。
- `ScalingService` 及会话协调：目标确认、开始应用、真正停止、重建和过期请求处理。
- 当前内容基础目标解析接口：提供同步目标变更，不把 RTSS 访问放到每帧渲染热路径。
